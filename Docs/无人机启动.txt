===================================== 多场景无人机启动命令 =====================================

目标：
1. 在城市 / target_seek 场景中验证已自动导入的 uav1_iris_depth_camera。
2. 在森林 / 机场场景中手动导入 uav1_iris_depth_camera。
3. 开启并查看无人机深度相机话题。
4. 测试 uav1 的移动控制话题。

【当前状态】
1. QY_MODEL/target_seek 中当前启用的是 uav1_iris_depth_camera，城市环境启动后会自动导入。
2. KD_MODEL/world/forestV3.world 和 KD_MODEL/world/airport 中没有预置无人机，需要手动 spawn。
3. uav2_iris_depth_camera 到 uav5_iris_depth_camera 在 QY_MODEL/target中_seek 中暂时被注释，当前不会自动导入。
4. uav1_iris_depth_camera 内部包含：
   - uav1_iris 无人机机体
   - uav1_depth_camera 深度相机
5. uav1_depth_camera 使用 libgazebo_ros_camera.so，相机命名空间为 /uav1。
6. uav1_iris 中已加入 gazebo_ros_planar_move 插件，可通过 /uav1/custom_cmd_vel 测试平面移动。

===================================== 准备环境 ==================================================

每个终端都先执行一次：

conda deactivate
which python3

确认 which python3 输出为：

/usr/bin/python3

然后执行：

export DELIVERY_ROOT=/home/wangantong/KD_all/go2_target_seek_delivery
cd $DELIVERY_ROOT/go2_ws_v2
source /opt/ros/humble/setup.bash
source install/setup.bash
export QY_MODEL_ROOT=$DELIVERY_ROOT/QY_MODEL
export KD_MODEL_ROOT=$DELIVERY_ROOT/KD_MODEL
export GAZEBO_MODEL_PATH=$QY_MODEL_ROOT/models:$KD_MODEL_ROOT/models:$GAZEBO_MODEL_PATH
export GAZEBO_MODEL_DATABASE_URI=""

===================================== 终端 1：启动场景 ==========================================

三个场景三选一。

城市 / target_seek 场景会自动导入 uav1_iris_depth_camera：

ros2 launch go2_config gazebo_target_seek_world.launch.py gui:=true world:=$QY_MODEL_ROOT/target_seek

森林场景不会自动导入无人机，需要启动世界后执行“终端 2：手动导入无人机”：

ros2 launch go2_config gazebo_target_seek_world.launch.py gui:=true world:=$KD_MODEL_ROOT/world/forestV3.world

机场场景不会自动导入无人机，需要启动世界后执行“终端 2：手动导入无人机”：

ros2 launch go2_config gazebo_target_seek_world.launch.py gui:=true world:=$KD_MODEL_ROOT/world/airport

如果已有 Gazebo 旧进程，先清理后再启动：

pkill -f gzserver
pkill -f gzclient

===================================== 终端 2：手动导入无人机 =====================================

城市 / target_seek 场景可跳过本节，因为 world 已自动导入 uav1。

森林 / 机场场景启动后，另开一个终端执行公共环境，再手动导入 uav1_iris_depth_camera：

ros2 run gazebo_ros spawn_entity.py -entity uav1_iris_depth_camera -database uav1_iris_depth_camera -x -15 -y -2 -z 2.0 -Y 0.0

说明：
1. -entity 是 Gazebo 中的实体名。
2. -database uav1_iris_depth_camera 会从 GAZEBO_MODEL_PATH 中查找 QY_MODEL/models/uav1_iris_depth_camera。
3. -x -y -z 是导入位置；森林 / 机场中如位置不合适，可调整坐标。
4. -z 2.0 表示初始高度 2 米，方便观察和避免与地面模型重叠。

===================================== 终端 3：确认无人机已导入 ==================================

执行公共环境后，查看 Gazebo 模型状态：

ros2 topic list | grep gazebo

查看场景里是否出现 uav1 相关话题：

ros2 topic list | grep uav1

正常情况下应能看到 uav1 的相机、IMU、GPS 或自定义移动相关话题。

也可以在 Gazebo 左侧模型列表中查找：

uav1_iris_depth_camera

===================================== 终端 4：查看无人机相机 =====================================

执行公共环境后，先列出 uav1 相机话题：

ros2 topic list | grep /uav1
ros2 topic list | grep camera

常用查看方式：

ros2 run rqt_image_view rqt_image_view /uav1/camera/image_raw

如果该话题名不显示，先用下面命令查看实际相机话题名：

ros2 topic list | grep image

然后把 rqt_image_view 后面的 topic 替换成实际输出的话题。

检查相机是否有频率：

ros2 topic hz /uav1/camera/image_raw

===================================== 终端 5：测试无人机移动 =====================================

执行公共环境后，查看 uav1 移动话题：

ros2 topic list | grep custom_cmd_vel

如果存在 /uav1/custom_cmd_vel，可以发布速度测试移动：

ros2 topic pub -r 10 /uav1/custom_cmd_vel geometry_msgs/msg/Twist "{linear: {x: 0.5, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 0.0}}"

停止移动时按 Ctrl+C 结束发布，再发送一次零速度：

ros2 topic pub --once /uav1/custom_cmd_vel geometry_msgs/msg/Twist "{linear: {x: 0.0, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 0.0}}"

向左 / 右平移示例：

ros2 topic pub -r 10 /uav1/custom_cmd_vel geometry_msgs/msg/Twist "{linear: {x: 0.0, y: 0.5, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 0.0}}"

原地偏航示例：

ros2 topic pub -r 10 /uav1/custom_cmd_vel geometry_msgs/msg/Twist "{linear: {x: 0.0, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 0.5}}"

===================================== 常见检查命令 ==============================================

查看所有 uav1 话题：

ros2 topic list | grep /uav1

查看相机话题：

ros2 topic list | grep image

查看相机频率：

ros2 topic hz /uav1/camera/image_raw

查看移动命令是否发出：

ros2 topic echo /uav1/custom_cmd_vel

取消 Gazebo 物理暂停：

ros2 service call /unpause_physics std_srvs/srv/Empty {}

===================================== 注意事项 ==================================================

1. 城市场景已测试完成：uav1 模型、RGB 图、深度图、点云、/uav1/custom_cmd_vel 均已出现。
2. 当前城市场景只自动导入 uav1，uav2 到 uav5 仍是注释状态。
3. 森林 / 机场场景不自动导入无人机，需要使用 spawn_entity.py 手动导入。
4. 无人机相机和多狗 3D 雷达同时运行会抢 GPU，RTF 可能下降。
5. 若 rqt_image_view 看不到 /uav1/camera/image_raw，先用 ros2 topic list | grep image 查实际话题。
6. 若 Gazebo 打印 libcurl SSL 相关提示，但场景和模型正常显示，可先忽略。
7. 如果需要启用 uav2 到 uav5，需要修改 QY_MODEL/target_seek 中对应 include 的注释，或用 spawn_entity.py 分别手动导入。
