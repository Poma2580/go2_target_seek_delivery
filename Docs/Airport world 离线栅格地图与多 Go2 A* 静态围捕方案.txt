# Airport world 离线栅格地图与多 Go2 A* 静态围捕方案

更新日期：2026-07-20

本文档记录本仓库中 airport 场景从 Gazebo world 生成离线栅格地图，以及使用该地图为三只 Go2
生成 A* 航点并交给原静态 waypoint 控制器执行的完整方案、实现位置、参数和验证方式。


一、总体目标
============

原 waypoint_encircle.py 使用人工填写的 approach 航点。改造后的结构把“路径规划”和“运动控制”
拆成两层：

  airport world
       │
       ▼
  world_to_grid 离线转换
       │
       ├── airport.pgm
       ├── airport.yaml
       ├── airport_collisions.csv
       └── airport_preview.svg
       │
       ▼
  PGM/YAML 读取 + 障碍膨胀
       │
       ▼
  三狗真实 odom + 自动可行围捕点
       │
       ▼
  八邻域 A* + 路径简化 + 航点重采样
       │
       ▼
  [(x,y,None), ..., (goal_x,goal_y,goal_yaw)]
       │
       ▼
  原 waypoint_encircle 控制器发布 /go2_N/cmd_vel

A* 只生成航点，不替换已经能工作的速度控制逻辑。manual 模式仍然保留，可用于 city、forest 或
回归比较。

三、从 world 生成原始栅格地图
============================

3.1 为什么不用雷达建图

airport 是已知仿真环境。直接解析 world 有以下优点：

  1. 不受雷达噪声、遮挡和机器人行驶轨迹影响；
  2. 不需要先控制机器狗遍历整个机场；
  3. 同样输入产生字节一致的地图，便于测试；
  4. 地图坐标直接使用 Gazebo 世界坐标，可直接配合 ground-truth odom；
  5. 能输出每一个 collision 的诊断记录，方便定位误判障碍。

3.2 airport 固定参数

  world 范围：        x=[-180,180] m，y=[-75,75] m
  分辨率：            0.20 m/cell
  地图宽高：          1800 x 750
  Go2 障碍高度切片： z=[0.03,0.80] m
  地图 origin：       [-180,-75,0]
  原始地图膨胀：      无
  最外边界：          1 个障碍栅格

地图生成阶段只描述场景原始 collision。机器人尺寸和跟踪误差在 A* 阶段通过 inflation_radius
处理，这样同一张原始地图可以供不同尺寸的机器人使用。

3.3 world 展开

转换器通过 fork/exec 无 shell 拼接地执行：

  gz sdf -p <world>

这样会展开 world 内的 model:// 引用。模型搜索路径合并以下来源：

  1. 可重复传入的 --model-path PATH；
  2. GAZEBO_MODEL_PATH；
  3. ~/.gazebo/models。

airport 使用的官方 Gazebo 模型必须完整存在于 ~/.gazebo/models，或者位于显式模型搜索路径中。
gz 返回非零、输出为空或 XML 无法解析时，转换器直接失败。

3.4 collision 和位姿

TinyXML2 遍历展开后的 world/model/link/collision，完全忽略 visual。世界 collision 位姿由模型、
link 和 collision 位姿递归相乘得到。无 pose 时使用单位变换；pose 按 SDF 的：

  x y z roll pitch yaw

解释。支持普通父子 pose 和 relative_to="__model__"。其他无法解析的 relative_to frame 会明确
报错，不能静默采用错误坐标。

所有模型无论 static 为 true 或 false，都按 world 初始位置写入地图，动态标志记录到 CSV。
uav1_iris_depth_camera 通过 --ignore-model 显式排除，其 collision 在 CSV 中记录为 ignored_model。

3.5 几何到世界 AABB

首版支持：

  box：       变换局部包围盒 8 个角点；
  cylinder：  使用 [-r,r] x [-r,r] x [-length/2,length/2] 的保守包围盒；
  sphere：    使用半径包围盒；
  mesh：      Assimp 加载 DAE/OBJ/STL，递归应用 Assimp 节点变换、DAE 单位、SDF scale 和
              collision 世界位姿，再合并全部顶点。

Gazebo/SDF 使用 Z-up。Assimp 加载 COLLADA 时配置为保留源文件 Z_UP，避免把飞机翼展错误变成
世界 Z 高度；DAE 的单位缩放仍然保留。

以下情况硬失败：

  mesh 文件缺失或 Assimp 解析失败；
  尺寸非正；
  AABB 存在非有限值；
  plane、heightmap、submesh 或其他未知 geometry；
  无法解析的 relative_to frame。

3.6 高度切片和栅格化

对于每个世界 AABB：

  max_z < 0.03： ignored_below_slice；
  min_z > 0.80： ignored_above_slice；
  XY 完全在地图外：ignored_outside_bounds；
  与高度切片相交：occupied，并投影完整 XY AABB。

机场地面、跑道和道路最高点约为 0.01 m，因此不会被当成 Go2 障碍。建筑、车辆、飞机轮子、
塔和其他与 Go2 高度相交的物体会保守占用。

栅格默认值为 254，障碍为 0。只要 AABB 与栅格面积存在正面积重叠就标记为占用，不只检查栅格
中心。PGM 图像行号为：

  row = height - 1 - grid_y

因此 world Y 正方向与 PGM 显示方向一致。最外一圈栅格设为障碍，阻止 A* 越界。

3.7 输出事务和诊断

转换器先写四个临时文件，全部写完后再替换正式文件；替换异常时恢复旧产物，避免半生成状态。

airport.yaml 使用：

  image: airport.pgm
  mode: trinary
  resolution: 0.2
  origin: [-180, -75, 0.0]
  negate: 0
  occupied_thresh: 0.65
  free_thresh: 0.25

airport_collisions.csv 字段为：

  model,link,collision,geometry,static,status,
  min_x,min_y,min_z,max_x,max_y,max_z,source_uri

airport_preview.svg 中：

  黑色：参与 A* 的原始障碍；
  绿色：低于高度切片的地面/道路；
  灰色：高于 Go2 高度切片的物体；
  文字：模型名称。

3.8 地图生成命令

  cd $DELIVERY_ROOT/go2_ws_v2
  source /opt/ros/humble/setup.bash
  colcon build --symlink-install --packages-select world_to_grid multi_go2_waypoint
  source install/setup.bash

  ros2 run world_to_grid world_to_grid \
    --world "$KD_MODEL_ROOT/world/airport" \
    --output-prefix "$DELIVERY_ROOT/go2_ws_v2/src/multi_go2_waypoint/maps/airport" \
    --bounds -180 -75 180 75 \
    --resolution 0.20 \
    --z-min 0.03 \
    --z-max 0.80 \
    --border-cells 1 \
    --ignore-model uav1_iris_depth_camera

重新生成源目录中的地图后，应再次构建 multi_go2_waypoint，使安装空间中的地图同步更新。

  origin：(-180,-75)；
  resolution：0.2；

  有效 obstacle collision：36；
  ignored_model collision：5；

四、A* 地图读取和安全膨胀
========================

4.1 为什么直接读 YAML/PGM

第一版 A* 不依赖 Nav2 planner_server，也不要求 map_server 正在运行。grid_astar.py 直接读取安装后的
airport.yaml 和 airport.pgm。这样依赖少、调用链短，适合作为老师要求的基础 A* 实现。

map_server 仍可用于 RViz 验证，但不是 A* 运行前提。

4.2 地图内部方向

GridMap 内部统一使用：

  gx 向 world X 正方向增长；
  gy 向 world Y 正方向增长；
  blocked[gy * width + gx] 表示占用。

世界坐标转栅格：

  gx = floor((world_x - origin_x) / resolution)
  gy = floor((world_y - origin_y) / resolution)

栅格中心转世界坐标：

  world_x = origin_x + (gx + 0.5) * resolution
  world_y = origin_y + (gy + 0.5) * resolution

读取 PGM 时执行 Y 翻转。地图外坐标直接报错。YAML 的阈值中间区域按障碍处理，防止未来出现
unknown 像素时被误认为自由空间。

4.3 障碍膨胀

原始地图只表示 collision AABB。A* 默认使用：

  inflation_radius = 0.55 m

实现不依赖 OpenCV 或 SciPy，而是使用整数圆形核膨胀 bytearray。栅格半径为：

  cell_radius = ceil(inflation_radius / resolution)

airport 中为 ceil(0.55/0.20)=3 个栅格，即最保守方向约 0.60 m。这个距离同时覆盖：

  Go2 机身/腿部空间；
  控制误差；
  waypoint 的 REACH_THRESHOLD=0.25 m 造成的提前切点和轻微切弯。

膨胀只存在于运行内存，不改写 airport.pgm。


五、基础 A* 算法
===============

5.1 邻域和代价

使用八邻域：

  上下左右：代价 1；
  四个对角：代价 sqrt(2)。

对角移动必须同时满足两个相邻正交栅格为自由，禁止从两个障碍接触的角点斜穿。

5.2 启发函数

使用适合八邻域的 octile distance：

  dx = abs(goal_x - x)
  dy = abs(goal_y - y)
  h = max(dx,dy) + (sqrt(2)-1) * min(dx,dy)

该启发函数不高估八邻域最短距离，因此基础 A* 仍能得到栅格代价意义下的最短路径。

5.3 数据结构和确定性

  open set：heapq 最小堆；
  g_score：字典；
  came_from：父节点字典；
  closed：bytearray；
  节点：一维 index=gy*width+gx。

邻居顺序固定，heap 中加入递增 serial 作为最终 tie-break。同样地图、起点和终点每次产生相同路径。
默认最大展开数量为地图总栅格数，防止异常输入无限占用计算时间。

5.4 明确失败而不直线降级

以下情况抛出 PlanningError：

  起点在障碍或地图外；
  终点在障碍或地图外；
  open set 耗尽仍不能到达；
  超过最大展开节点数。

规划失败后 waypoint_encircle 会令全部机器狗保持零速度，不会静默退化为直接向目标直线行驶。


六、围捕终点可行性
==================

airport pickup 的 collision AABB 约为：

  x=[78.76,81.30]
  y=[-28.01,-22.27]

原配置 target=(80,-25,-1)，encircle_radius=3.0。三个理论围捕点中，约
(78.62,-27.67) 在原始障碍内；加入 0.55 m 膨胀后，还有另一个点离 pickup 太近。

处理方法不是单独移动某个点，而是同步扩大整个围捕圆：

  1. 从请求半径开始生成均匀围捕点；
  2. 在膨胀地图中检查所有点；
  3. 每次增加一格，即 0.20 m；
  4. 所有点都自由后停止；
  5. 超过 max_goal_radius_expansion 后仍不可行则整体失败。

当前 airport 在默认参数下得到实际半径 4.0 m，仍然保持三只狗组成等边三角形并朝向目标中心。


七、A* 路径到控制航点
====================

7.1 为什么不能直接使用所有栅格点

0.20 m 分辨率下，80 m 路径可能包含四百多个点，而原控制器 REACH_THRESHOLD 为 0.25 m。直接执行
全部点容易频繁切换、抖动，并产生大量日志。

7.2 路径简化

grid_astar.py 使用 supercover 直线检查：

  1. 从当前锚点开始；
  2. 寻找后方最远且直线完全自由的路径点；
  3. 删除中间多余栅格；
  4. 在穿过栅格角点时同时检查两侧格子，避免贴角穿障碍。

所有检查都在膨胀地图上进行。

7.3 航点重采样

简化后的长直线按 max_waypoint_spacing=1.5 m 重新均匀插点。中间点格式为：

  (x, y, None)

最后一个点保留准确的围捕世界坐标和朝向：

  (goal_x, goal_y, goal_yaw)

生成结果可直接赋给 dog.waypoints，原 control_one() 不需要知道航点来自人工配置还是 A*。


八、与 waypoint_encircle 的状态机集成
====================================

8.1 manual 模式

  planner_mode:=manual

行为与原代码一致：使用 SCENES 中的 approach 航点，再追加动态计算的围捕终点。manual 是默认值，
用于保证原有 city/forest 流程不受影响。

8.2 astar 模式

  planner_mode:=astar

启动顺序：

  1. 从 ament 安装目录加载 airport.yaml/PGM；
  2. 构建膨胀地图；
  3. 创建三只 DogController，但 waypoints 暂为空；
  4. 等待 /go2_1/odom、/go2_2/odom、/go2_3/odom；
  5. 使用第一帧真实 odom，而不是只相信配置出生点；
  6. 自动求可行围捕半径；
  7. 保留原 assign_encircle_points()，按三狗到三个终点的总欧氏距离最小分配终点；
  8. 为每只狗分别运行 A*、简化和重采样；
  9. 三条路径全部成功后统一写入 dog.waypoints；
 10. planning_complete=true，原 20 Hz 控制循环开始执行。

三条路径是“全有或全无”：不会出现 go2_1 已经运动，而 go2_3 随后才发现无路可走的情况。

8.3 原运动控制保持不变

每个周期计算当前位置到当前 waypoint 的距离和方向：

  yaw 误差大于 0.7 rad：原地转向；
  否则按比例前进；
  位置误差小于 0.25 m：切换下一航点；
  最终航点到达后：原地对准目标中心；
  三狗完成后：持续发布零速度。

要求 spawn launch 使用 use_ground_truth_odom:=true。本仓库的 spawn_go2_velodyne_N.launch.py 默认
已经为 true，airport 启动脚本满足该条件。


九、ROS 参数
============

原参数：

  scene                       city / forest / airport
  num_dogs                    默认 3
  target_x                    覆盖场景目标 X
  target_y                    覆盖场景目标 Y
  target_yaw                  覆盖目标朝向
  encircle_radius             请求的围捕半径

A* 新参数：

  planner_mode                manual 或 astar，默认 manual
  map_yaml                    地图 YAML；airport 留空时自动找安装地图
  inflation_radius            默认 0.55 m
  max_waypoint_spacing        默认 1.5 m
  max_goal_radius_expansion   默认最多向外扩 3.0 m

非 airport 场景若选择 astar，必须显式提供对应 map_yaml，防止错误使用 airport 地图。
