推荐速度区间：

| 场景 | 线速度上限 m/s | 角速度上限 rad/s | 说明 |
| --- | --- | --- | --- |
| 稳定调试 / SLAM / 初期导航 | 0.2 - 0.35 | 0.4 - 0.7 | 最适合先跑通定位、建图、路径跟踪 |
| 普通导航 / 跟踪 | 0.35 - 0.6 | 0.7 - 1.0 | 推荐下一步尝试的主区间 |
| 开阔场景快速跟踪 | 0.6 - 1.0 | 1.0 - 1.5 | 需要 odom、costmap、局部规划都稳定 |
| 真实 Go2 快速运动 | 1.0 - 2.0+ | 视低层控制而定 | 不建议一开始用于 Nav2 自主导航 |
| 厂商物理极限 | 2.5 - 5.0 | 不作为导航参数 | 更像手柄 / 专用运动模式 / 实验室跑速 |

当前 go2_config 的 CHAMP 腿控速度上限：

```yaml
max_linear_velocity_x : 0.3
max_linear_velocity_y : 0.25
max_angular_velocity_z : 0.5
```

说明：
- teleop_twist_keyboard 终端里的 speed / turn 只是发布到 `/cmd_vel` 的目标值。
- 真正执行前会被 CHAMP 的 gait 参数限幅。
- 调 Nav2 或跟踪时建议保持：Nav2 速度上限 <= gait 速度上限。

建议第一轮稳中偏快测试：


=================================== 实现进展（0623 已完成）=========================================
新增 ROS2 包 multi_go2_waypoint，实现三狗联合 waypoint 围捕控制节点：
    路径：go2_ws_v2/src/multi_go2_waypoint/
    节点：multi_go2_waypoint_encircle（waypoint_encircle.py）
    可执行：ros2 run multi_go2_waypoint waypoint_encircle

按半径 r=2m、目标 SUV(42, -20, yaw=-0.5) 解算的等边三角形围捕终点（yaw 朝内侧目标）：
    go2_1 终点: x=40.245  y=-19.041  yaw=-0.500
    go2_2 终点: x=41.953  y=-21.999  yaw= 1.594
    go2_3 终点: x=43.707  y=-18.957  yaw=-2.594

最终 waypoint 序列（None 表示中途路点，到点即切下一个；终点带 yaw 表示到位后做最终朝向对齐）：
    go2_1: (21,0,None) -> (38,-8,None) -> (40.245,-19.041,-0.500)
    go2_2: (30,-30,None) -> (41.953,-21.999,1.594)
    go2_3: (45,0,None) -> (43.707,-18.957,-2.594)

控制逻辑：
    1. 每只狗订阅 /go2_N/odom，发布 /go2_N/cmd_vel（geometry_msgs/Twist）。
    2. 状态机 tracking -> final_yaw_align -> done。
    3. 位置追踪比例控制：yaw 误差 >0.7rad 原地转，否则边走边微调；
       线速度上限 0.45、角速度上限 0.9（与 gait/导航限速一致）。
    4. 到达带 yaw 的终点后进入 final_yaw_align，对准内侧目标（阈值 0.1rad）。
    5. 三狗全部完成后持续发布零速度，节点 Ctrl+C 退出时也补发一次零速，防止漂移。

前提：waypoint 为世界系绝对坐标，依赖世界系真值里程计
    （spawn_go2_velodyne_N.launch.py 的 use_ground_truth_odom 默认 true，正常导入即可）。

启动顺序（每个终端先 conda deactivate 确认 which python3 为 /usr/bin/python3）：
    终端1: ros2 launch go2_config gazebo_target_seek_world.launch.py gui:=true
    终端2/3/4: ros2 launch go2_config spawn_go2_velodyne_{1,2,3}.launch.py（逐只等稳定）
    终端5: ros2 run multi_go2_waypoint waypoint_encircle

测试结果：三只狗依次走完各自 waypoint，最终在 SUV 周围围成等边三角形并各自对准内侧目标后停车，
节点日志输出“所有机器狗已完成围捕，持续发布零速度。”，围捕成功。

=================================== 动态围捕实现进展（0624 已完成）=========================================
目标：三只 Go2 实时追踪 target_seek 里绕房子行走的行人 actor(walking_target)，
      沿回路追上后维持一个随行人运动方向旋转、半径 1.5m 的三角编队围捕。

一、行人 actor 路线修正（QY_MODEL/target_seek 的 <trajectory>）
    1. 修正“走直线扭身/拐角绕圈”：每段直线两端 yaw 一致、拐角原地转 2s、
       yaw 递增(逆时针全程左转)防 270° 反转。
    2. 矩形路线整体外扩 1m、速度降到约 0.35 m/s，给 1.5m 围捕半径腾出墙体间隙。
       新角点：(41,4) -> (41,36) -> (-13,36) -> (-13,4) 闭环。

二、行人状态桥接节点 actor_state_publisher（multi_go2_waypoint 包）
    - 订阅 /gazebo/model_states，取 walking_target 位姿，发布 /walking_target/odom。
    - actor 由 <script> 动画驱动、不走物理，model_states 里 twist 速度恒为 0，
      故用相邻帧位置差分 + 一阶低通自算世界系速度。
    - 找不到模型时节流告警，不发伪造位姿；使用仿真时间。
    - 运行：ros2 run multi_go2_waypoint actor_state_publisher --ros-args -p use_sim_time:=true

三、动态围捕节点 dynamic_encircle（节点名 multi_go2_dynamic_encircle）
    三段式状态机（每只狗独立）：
        approach  ：走预设安全路点(下方)绕开建筑、上到行人回路(环)附近。
        catch_up  ：把狗与行人都投影到矩形环上，沿环就近方向追人；前瞻点沿环取(自动绕角)、
                    恒定巡航速度持续推进(修复了在角点减速卡住的问题)，结构上不穿越中心房屋。
        formation ：追到行人 2m 内后，做绕行人 1.5m 的旋转三角围捕；被甩开 >4m 退回 catch_up(滞回)。
    关键设计：
        - 编队朝向用行人“运动航向”atan2(vy,vx)，不用 actor 那个在拐角猛甩的 yaw；
          低速冻结航向 + 变化率限幅，拐角处编队点平滑不甩。
        - 狗朝向始终对齐自身前进方向（不强制面向行人）。
        - 全程加速度限幅(accel_lin/accel_ang)，速度不突跳；行人/自身里程计超时即持续发零速。
    主要可调参数：
        formation_radius=1.5, catch_speed=0.6, catch_lookahead=1.5,
        catch_radius=2.0, revert_radius=4.0, max_linear=0.65, max_angular=0.9。
    环角点 LOOP_CORNERS 须与行人(加宽后)矩形一致。
    运行：ros2 run multi_go2_waypoint dynamic_encircle --ros-args -p use_sim_time:=true
