==================================================
2026-07-07 改动说明：多狗“拦截式围捕”动态追踪（三狗联合调通）
==================================================

背景：0701 只调通单狗(go2_1)稳定跟随，多狗三角编队未通。本轮把三狗联合做成
更直观的“拦截式围捕”：两只狗绕到行人前方、停下转身、一起冲刺合围，冲进设定距离
的那一瞬即算任务成功（之后不再管狗与人）。已在 target_seek 世界中初步跑通。

一、整体方法（dynamic_encircle.py）
角色分工：
  - go2_1（感知手）：唯一带 RGB-D+YOLO，先沿基准矩形回路 catch_up 贴边追上行人，
    贴近后进入 formation，用 B 方案“锁定行人的定距跟随”跟在行人后方约 r 米，
    机身始终对准行人、相机不丢视野；作为合围的“后方一角”，不参与冲刺。
  - go2_2（前方拦截手）、go2_3（外侧斜插手）：冲刺手，绕到行人前方后同步冲刺围捕。

冲刺手状态机：approach -> to_stage -> staged -> charge -> done
  1. approach：走预设安全路点绕开建筑、抵达行人回路附近（沿用 0624 路点）。
  2. to_stage：在“自己的车道回路”上，跟到行人【前方 ahead 米】处（沿弧长超前）。
     - go2_2 超前 ahead_intercept=15m；go2_3 超前 ahead_flank=12m。
  3. staged：先到的狗【持续保持】在行人前方（stage 点每拍随行人更新，狗同步前移，
     绝不被行人追上/走过），等另一只也到位。
  4. charge：两只都 staged 后，同步屏障一起放行 -> 脱离车道、对准行人直线冲刺。
  5. done：任一狗冲进 r_final=5m 即冻结；两只都 done 打印“★ 围捕完成”，任务成功。

二、关键设计点
1. 【车道回路，修拐角转圈根因】早期用“径向逐点外移”给两狗分道，在矩形拐角处外移方向
   带沿边分量，导致前瞻目标弧长非单调，狗就地打转、一直不走。改为“同心外扩矩形车道”：
   把基准回路四角整体外扩各自 lane 米（go2_2 外扩 intercept_offset=1.5、go2_3 外扩
   side_offset=3.0），每狗走一条干净的大矩形回路，直边垂直外移、拐角弧长单调，不再转圈；
   两条车道横向错开，也天然避免两只冲刺手相撞。
2. 【stage 点实时更新】stage 点 = 行人当前位置投影到本车道回路 + ahead 弧长，每拍(0.05s)
   重算，时刻跟人。staged 只是个“到位旗标”（供同步屏障），运动不冻结——用比例限速
   lin=clamp(k_linear*|Δ弧长|,0,catch_speed)*gate 持续把自己维持在行人前方。
3. 【同步屏障】两只冲刺手都 staged 才在同一拍一起切 charge，保证“同时冲刺”。
4. 【边走边转，禁硬原地转】全程 gate=max(cos(yaw_err),0.25)：CHAMP 四足纯原地转
   (lin=0)几乎迈不动腿，故转身/冲刺都留一点前进量，走弧线过渡。

三、主要参数（dynamic_encircle.py 节点参数）
  ahead_intercept=15.0 / ahead_flank=12.0  两冲刺手的前向保持距离（沿车道弧长）
  intercept_offset=1.5 / side_offset=3.0   两条车道相对基准回路的外扩量
  r_final=5.0                              冲进此距离即完成
  stage_arrive_tol=1.0                     到位判定容差
  charge_speed=0.65                        冲刺速度
  formation_radius(r)=2.0                  go2_1 后方跟随距离
  catch_speed=0.6 / k_linear=0.8 / k_angular=0.9 / catch_lookahead=1.5

四、启动
  Scripts/start_three_go2_dynamic_tracking.sh 已恢复 go2_2/go2_3 的 spawn，一键拉起
  世界→go2_1(RGB-D)→actor 真值→感知→控制→rqt→误差评估；目标源用
  /go2_1/target_estimated/odom。（务必先 conda deactivate，which python3 为 /usr/bin/python3。）

五、现状与缺陷不足
1. 功能已初步实现：go2_1 后方跟随做感知，go2_2/go2_3 绕到前方、同步冲刺，能形成合围。
2. 【启动非常不稳定】脚本顺序拉起多狗时常遇底层问题：
   - 某只狗 spawn 时翻倒（此前修过、仍会偶发复现，疑似多狗共享 gzserver 时控制器/接触
     初始化时序抖动）；
   - YOLO 检测框卡顿/掉帧，go2_1 瞬时丢失行人视野，导致目标估计缺失、追捕段停摆。
   目前只能靠重启脚本规避，需后续从启动时序与感知鲁棒性上根治。
3. 目标源为 go2_1 单目感知，视野受限/遮挡时估计会抖；冲刺手完全依赖 go2_1 的感知。
4. 参数（ahead/车道外扩/冲刺速度）尚需针对不同行人段（直道/拐角）进一步调稳。
5. 仍不支持任意数量 go2；角色分工与车道为三狗写死。
